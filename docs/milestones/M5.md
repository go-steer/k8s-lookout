## Exit check A — multi-cluster staged stockout rolls up as a join

`internal/watch/m5_corpus_rollup_test.go`
(`TestDrill_MultiClusterRollup_Stockout`): TWO sentinel dispatcher
instances (`cluster=prod-east` / `prod-west`) run the same scripted
zonal stockout and quota-block shapes through the REAL pipeline
against stub-format captures. Captured on the wire (2026-07-26 run,
verbatim; the §8 identity fields are the #59 additions):

```json
{"kind":"capacity.stockout", …,"cluster":"prod-east","zone":"us-east1-b","source":"sentinel","severity":"critical","fingerprint":"sha256:0aad765472e43524e5fcc0004675a5173257699c20942b59e226a9162745034c","context":{}}
{"kind":"capacity.stockout", …,"cluster":"prod-west","zone":"us-east1-b","source":"sentinel","severity":"critical","fingerprint":"sha256:0aad765472e43524e5fcc0004675a5173257699c20942b59e226a9162745034c","context":{}}
```

The fleet-side rollup is asserted **as a join, not a parse** — group both
streams by `fingerprint` alone:

```
fleet group sha256:0aad7654…5034c → clusters [prod-east prod-west]   (capacity.stockout)
fleet group sha256:95fa2f13…fbd18 → clusters [prod-east prod-west]   (capacity.quota_blocked)
```

One fleet-level group per failure class, a member per cluster,
identical fingerprints, differing `cluster`, shared `zone` (zone is
inside the hash — zone-scoped causes are what rollup must group; the
test also pins that a different zone splits the group). Storm
fingerprints are covered kind-level in the same test. Push/pull
parity — the same class key from the sentinel stamp and from a scan
finding — is pinned by `TestFingerprintParity_PushAndScan`.

**Remaining human step:** point a real fleet-level consumer at two
staged clusters and run this join over its ingest — the schema side is
frozen (v1) and contract-tested; nothing further ships from this repo
for it.

## Exit check B — corpus harvester contract, end-to-end

`TestDrill_CorpusHarvest_EndToEnd`: a scripted full lifecycle through
the REAL dispatcher against a fake daemon that captures in
`dev/drills/stub-daemon.py`'s exact line format — critical
`k8s-event` inject (enrichment bundle attached) → suppressed
duplicate → §9.4 `triaged` and `actioned` records written through the
real store and exported into the capture → `resolved` outcome routed
into the bound session (record auto-flips to resolved). The harvester
(`pkg/corpus`) then extracts, by pure schema walks, **exactly one
complete labeled trajectory** (2026-07-26 run, verbatim):

```json
{"session":"stub-sess-0001","cluster":"prod-east","fingerprint":"sha256:e2957792a0b3ad9e29db2051dbc69ff01dfe3a52da8dbb6d1331aa44fe946f8b","symptom":{"kind":"k8s-event","reason":"CrashLoopBackOff","namespace":"prod","kind_of_object":"Pod","name":"api-0","uid":"abc-123","first_seen":"2026-07-24T10:00:00Z","message":"Back-off restarting failed container"},"diagnosis":{"enrichment_bundle":true,"triage_status":"triaged","root_cause":"DB connection string invalid in checkout-config","session":"stub-sess-0001"},"action":{"status":"actioned","action":"PR #402 opened; config rollout pending"},"outcome":{"kind":"resolved","resolution":"recovered","resolved_at":"2026-07-24T10:07:30Z","cleared_after":"2m30s","observed_stable_for":"5m0s"},"label":"recovered","followups":0,"complete":true}
```

Every §9.3 stage present — symptom → diagnosis → action → externally
verified outcome — and the ground-truth label comes from the
structured `resolution` field, never prose. `pkg/corpus` unit tests
additionally pin: watchboard sessions yield no trajectory, unresolved
incidents stay unlabeled/incomplete, and a `resolved.reverted` after a
`resolved` relabels the trajectory `reverted` (a fix that failed to
stick is negative ground truth).

**Remaining human step — the real-incident trajectory:** run any GKE
drill runbook (`dev/drills/*.md`) against a real cluster with the
stub daemon (or a captured real daemon log) as the session sink,
write triage status at each transition per the playbooks, let the
sentinel observe the real fix, then:

```sh
kubectl logs stub-daemon > capture.log
lookout triage status --store=/var/lib/lookout/lookout.db --fingerprint=<fp> --format=json >> capture.log   # export the records
go run ./dev/tools/harvest-corpus capture.log
```
