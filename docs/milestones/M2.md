### Drill A — node failure: 1 storm session, not 30

Deployment `stormlab/victim`, 30 pause-style pods pinned by nodeSelector
to `kl-m2-worker2`; baseline snapshot of the stub log; then
`docker stop kl-m2-worker2` at 00:50:38 — a hard kubelet death, the
faithful `Ready→NotReady` replay.

Timeline (sentinel log):

```
00:51:18 fire node_notready pod=/kl-m2-worker2 → sid=stub-sess-0005 (mode=per-incident)
00:51:18 fire NodeNotReady pod=kube-system/kube-proxy-pkx94 → sid=stub-sess-0006 (mode=per-incident)
00:51:18 enrich storm Node kl-m2-worker2: 5273B (outcome=ok, sections=1, truncated=false, errors=0)
00:51:18 storm formed on Node kl-m2-worker2: 3 incidents across 2 namespace(s) → sid=stub-sess-0007 (mode=per-incident)
00:51:18 storm attach NodeNotReady stormlab/victim-… (sid=stub-sess-0007, members=4)
   ⋮  (one attach line per member)
00:51:20 storm attach NodeNotReady stormlab/victim-7d47b46468-mnf6b → Node kl-m2-worker2 (sid=stub-sess-0007, members=33)
```

40 seconds from `docker stop` to detection; the leading
`objectstate.node_notready` opened the node incident BEFORE the reactive
`NodeNotReady` event (which then joined its dedup family, as designed);
storm formed the same second; all 33 members attached within 2 seconds.

**The headline count** — 33 affected objects (30 victims + the node +
`kube-proxy` + `kindnet` DaemonSet pods; system pods on a dead node are
real storm members), and the stub's complete session/inject ledger for the
burst window:

```
SESSION-CREATE ×3   (stub-sess-0005, -0006, -0007)
INJECT sid=stub-sess-0005 kind=objectstate.node_notready   (the seed incident)
INJECT sid=stub-sess-0006 kind=k8s-event                   (2nd pre-storm arrival)
INJECT sid=stub-sess-0007 kind=storm                       (THE storm session)
INJECT sid=stub-sess-0007 kind=storm.member          ×30
INJECT sid=stub-sess-0005 kind=storm.member_superseded
INJECT sid=stub-sess-0006 kind=storm.member_superseded
```

**3 sessions, not 33**: ONE storm session plus the burst's first two
arrivals, which fired per-incident before the formation threshold
(`--storm-min=3`) was reachable — §7.5 says the first incidents of a burst
inherently may — and were immediately superseded into the storm
(`kind=storm.member_superseded` pointers in their sessions; dedup bindings
rebound, so their followups and outcomes route to the storm). Metrics
agree: `storm_members_total{attached}=33`, `{superseded}=4`,
`{suppressed}=2` (both storms), `storms_formed_total=2`.

### Drill B — fix-verify without agent polling

Deployment `fixlab/payment`: busybox whose command reads a ConfigMap-
mounted file and `exit 1`s on `mode=crash` — a crashloop whose FIX does
not replace the pod, so recovery judges the same UID end to end.

1. **00:54:01** applied; **00:54:07** (six seconds later) `fire BackOff
   pod=fixlab/payment-869d9b5594-d6gtm → sid=stub-sess-0008`. The initial
   inject is the frozen `k8s-event` payload with the §7.6
   `enrichment.bundle` attached (radius section naming the ReplicaSet,
   node, and same-node neighbors).
2. **00:55:37** the fix: `kubectl -n fixlab patch configmap payment-config
   --type merge -p '{"data":{"mode":"ok"}}'`. Nothing else touched; no

   15 s tracker tick) — the sentinel injected into the SAME session:

## Observations and gaps found by the drill (not fixed in this PR)

1. **Shipped ClusterRole cannot feed two enrichment sections.**
   `deploy/12-clusterrole-watcher.yaml` grants `deployments list/watch`
   but not `get`, and no `pods/log` — so in-cluster enrichment always
   loses the spec stage (`enrichment_error stage=spec … cannot get
   resource "deployments"`) and the logs section (`log.fetch_error …
   cannot get resource "pods/log"`). Failure honesty worked exactly as
   designed (trailers + `enrichment_failures_total{stage="spec"}=5`,
   `outcome=partial`), but the default deployment silently caps enrichment
   at radius(+delta). Fix: add `get` on `apps/deployments` (and
   `apps/statefulsets`/`daemonsets` when their incidents enrich) and `get`
   on `pods/log` to the ClusterRole.
2. **Node-scoped incidents have no clearance observer (§7.4 gap).** The
   object-state source emits `objectstate.node_notready` but only pods are
   judgeable, so the node's own incident never resolves — and therefore a
   node-anchored storm can never emit its aggregate `kind=resolved`
   (drill A ended 32/33 members cleared; the storm will only close via the
   silent 30-minute idle TTL). The bootstrap storm — all-pod members —
   resolved fine, isolating the gap precisely: a node Ready→NotReady
   observer is missing.
3. **Live-graph enrichment radius mislabels existing ConfigMaps/Secrets.**
   The storm-mode read path renders mount-referenced-but-unwatched objects
   as `radius.missing reason=ReferencedNotFound` ("referenced by the
   neighborhood but not observed on the API server") — drill B's
   `payment-config` exists, but the topology graph deliberately holds it
   identity-only (§6.3). Technically hedged, practically misleading for an
   agent deciding whether a reference is dangling. The radius check should
   distinguish "not watched by this index" from "dangling".
4. **The storm inject undersells the final blast radius.** The formation
   payload carries `affected_count` at formation time (3); the eventual
   size (33) only accumulates through per-member `storm.member` followups
   ("now N incidents"). Correct, but the design's headline number lives in
   followups rather than on one record; a storm-summary refresh (or
   count-carrying member payloads) would let fleet consumers and playbooks read the
   size without folding the session.

> **Status (2026-07-26): all four observations are closed.** Item 1 was
> fixed by #37 (ClusterRole `get` grants). Items 2–4 are fixed together
> in the drill-observations fix PR: (2) the object-state source's node
> informer now feeds a `NodeClearance` observer — node Ready=True and
> stable for the window → `kind=resolved` (resolution=recovered), so a
> node-anchored storm's aggregate outcome fires once ALL members
> including the node incident clear; (3) the radius section claims
> `radius.missing reason=ReferencedNotFound` only for kinds the
> snapshot's ingest actually watches (`graph.Snapshot.Watches`) — an
> unobserved neighbor of an unwatched kind (the live graph holds
> mounted ConfigMaps/Secrets/PVCs identity-only) renders as
> `radius.neighbor` with `observed=unknown`, while full-List one-shot
> bundles are unchanged; (4) the formation `kind=storm` payload stays
> byte-frozen, and size freshness rides a NEW schema-stable
> `kind=storm.update` followup into the storm session
> (`affected_count`, `namespaces_count`, `new_members_since_last`) when
> membership doubles or grows by 10 since the last report, at most one
> per minute.
