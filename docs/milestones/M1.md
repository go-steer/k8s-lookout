## Exit check (2026-07-24, kind)

Environment: kind v0.31.0 (node `kindest/node` v1.35.0, containerd 2.2.0),
kubectl client v1.35.6, docker 29.6.1. Image `lookout:m1-check` built from
HEAD and side-loaded into the cluster; the investigation itself ran the
same HEAD binary from the host against the cluster's kubeconfig (the CLI
path an operator/agent uses; the image path is exercised by `lookout
version` + entrypoint checks and was validated end-to-end in M0).

Seeded state, namespace `shop`:

- Deployment `checkout` (2 replicas, busybox script logging INFO/WARN/ERROR
  lines), env from ConfigMap `checkout-config` key `log.level` and — the
  sanitizer target — env `DB_PASSWORD` from Secret `checkout-db`, whose
  value is the marker `SUPERSECRETVALUE_M1`. Service `checkout` selects it.
- Then broken twice over: image updated to the nonexistent tag
  `busybox:1.36-nonexistent-m1` (new ReplicaSet pod → ImagePullBackOff;
  RollingUpdate keeps the 2 old pods serving) and key `log.level` removed
  from the ConfigMap (the current pod template now references a missing
  key).
- Healthy Deployment `web` alongside, to confirm zero-nominal-state (it
  never appears in any output below).

### Sanitizer proof

The marker was verifiably in the cluster
(`kubectl get secret checkout-db -o jsonpath='{.data.password}' | base64 -d`
→ `SUPERSECRETVALUE_M1`) and the broken workload mounted it as env, so it
sat directly on the paths spec/bundle/edges/mcp render. Every stdout and
stderr byte of every invocation above (20 capture files, including the
full MCP JSON-RPC session) was grepped:

```
$ grep -r SUPERSECRETVALUE_M1 /tmp/kl-m1-evidence/          # → no matches (exit 1)
$ grep -r U1VQRVJTRUNSRVRWQUxVRV9NMQ /tmp/kl-m1-evidence/   # base64 form → no matches (exit 1)
```

The value's only traces in any output are the *reference*
(`DB_PASSWORD=secretKeyRef:checkout-db.password`) and the length
(`keys=password(19B)`). Scope note: §6.5 guards what lookout renders from
cluster objects; an application that prints its own secret into its log
stream is masked only when it is credential-shaped (key-anchored, JWT,
PEM, …) — the documented free-form recall gap in `pkg/emit/sanitize.go`.

Cleanup: `kind delete cluster --name kl-m1`; test image removed.

### Verdict

Exit criterion met: the double-fault incident was fully root-caused with
lookout tools alone (no kubectl reads were needed for the diagnosis);
`health` answered the cluster question in one call with an
always-answering scorecard; and the planted secret value reached no output
surface, CLI or MCP.
