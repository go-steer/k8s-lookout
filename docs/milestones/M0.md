## Exit criterion

> Existing watcher deployment swaps images with zero config change.
> — DESIGN.md §14, M0 row

Mechanism: the predecessor image's entrypoint was the watcher binary and
deployments pass bare watcher flags via `args:`. This image sets
`ENTRYPOINT ["/lookout", "watch"]`, so the same `args:` splice in behind
`watch` unchanged.

## Exit check (2026-07-24, kind)

Environment: kind v0.31.0 (node `kindest/node:v1.35.0`), kubectl client
v1.36.2, docker 29.6.1.

Procedure:

```
docker build -t lookout:m0-check --build-arg VERSION=m0-check .
kind create cluster --name kl-m0
kind load docker-image lookout:m0-check --name kl-m0
kubectl create namespace agent-triage
kubectl -n agent-triage create secret generic k8s-event-watcher-token --from-literal=token=<test token>
kubectl apply -f deploy/11-serviceaccount-watcher.yaml \
              -f deploy/12-clusterrole-watcher.yaml \
              -f deploy/13-clusterrolebinding-watcher.yaml   # unmodified
kubectl apply -f <stub daemon manifest>                      # see below
kubectl apply -f <51-deployment-watcher.yaml, image line changed>
kubectl apply -f <busybox pod running `sh -c "echo boom; exit 1"`>
```

### What differed from the shipped manifests, and why

- `51-deployment-watcher.yaml`: exactly two lines changed —
  `image: ghcr.io/go-steer/lookout:v0.1.0` → `image: lookout:m0-check`
  (the image under test) and `imagePullPolicy: IfNotPresent` → `Never`
  (kind side-loads the image; there is no registry to pull from). The
  `args:` block, env, probes, ports, RBAC, and everything else were
  byte-identical to the shipped manifest. `imagePullPolicy` is a
  test-harness artifact, not a config change a real deployment would
  make — a real swap changes the image line only.
- RBAC manifests (`11-`/`12-`/`13-`) applied unmodified.
- Out-of-band prerequisites a real deployment already has: the
  `agent-triage` namespace, the `k8s-event-watcher-token` secret the
  shipped manifest references, and a daemon answering at
  `core-agent.agent-triage.svc.cluster.local:7777`. For the last one the
  check used a stub HTTP server (python, ~40 lines) behind a Service
  named `core-agent` implementing the two endpoints the sidecar speaks:
  `POST /sessions` → 201 `{"sessionID": ...}` and
  `POST /sessions/<sid>/inject` → 200, logging request bodies. The stub
  substitutes for a live core-agent daemon; it required no change to the
  watcher manifest — the shipped `--daemon-url` resolved to it as-is.

Note on `--dry-run`: it was not used in-cluster because dry-run
deliberately skips building the kube client (`internal/watch/main.go`,
"skip in dry-run to avoid needing a real cluster") — a dry-run watcher
never starts the informer, so it cannot exercise the event path. The
stub-daemon approach validates strictly more (real informer → filter →
dedup → session create → inject over the wire) with strictly fewer
manifest deviations (none).

### Verdict

Exit criterion met. With namespace, token secret, and a reachable daemon
in place — all preexisting in a real deployment — the shipped manifest
ran the new image with only the image line changed, produced
behavior-identical logs, wire payloads, metrics, and probe endpoints.
