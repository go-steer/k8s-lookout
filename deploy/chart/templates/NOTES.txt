Two prerequisites the chart does NOT create, because getting either
wrong is silent:

  1. The Secret holding the daemon bearer token:

       kubectl -n {{ .Release.Namespace }} create secret generic {{ .Values.daemonToken.secretName }} \
         --from-literal={{ .Values.daemonToken.secretKey }}=<token>

     It is not a chart value on purpose — a token passed as a value is
     written into the stored release manifest, where anyone who can
     read the release can read the token.

  2. A reachable core-agent daemon. Right now the sentinel is pointed at:

       {{ range .Values.args }}{{ if hasPrefix "--daemon-url=" . }}{{ trimPrefix "--daemon-url=" . }}{{ end }}{{ end }}

Check it came up:

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "lookout.fullname" . }}
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "lookout.fullname" . }} | head -40

The startup log names every source it enabled and every one it skipped,
with the reason. A source skipped for a missing grant is reported, never
silently dropped — if a source you expected is absent, the reason is in
those lines.
